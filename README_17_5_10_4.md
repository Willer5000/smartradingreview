# Commit 17.5.10.4 — Stable Market Identity + Execution ABI

Base exacta auditada: GitHub `d94b6d2bb2b006bdd8064e333e0e3407d82a7eba` (17.5.10.3).

## Objetivo
Eliminar la condición de carrera que podía hacer que un análisis Futures/Multi-Activo fuese tratado temporalmente como Spot y terminara en `unexpected keyword argument execution_observations`.

## Política de señales
**Calidad, no cantidad.** Este commit no introduce mínimos, máximos, cuotas ni objetivos de señales. Tampoco baja Safety, Entry, SL, TP, R/R, Publication ni leverage para producir actividad. Si varias oportunidades independientes superan realmente el mismo contrato técnico pueden publicarse; si ninguna lo supera, cero sigue siendo válido. La deduplicación por activo×TF evita duplicados, no limita oportunidades de calidad.

Entry/SL/TP conservan el motor existente: selección de Entry por evidencia estructural y refinamiento Futures de la pareja SL/TP antes de Safety/Publicación. 17.5.10.4 no cambia sus thresholds ni sus scores; sólo garantiza que el candidato llegue al motor correcto y que un fallo runtime no se disfrace como `0 errores`.

## Cambios
- identidad Spot/Futures determinada por el contrato del engine, no por `_skip_supabase_register`;
- adaptador ABI único `execution_abi_175104.py` para Futures y Multi-Activo;
- llamada Entry/SL/TP uniforme con `execution_observations`;
- un fallo de ejecución cuenta como error/retry y no reemplaza el último snapshot válido;
- Multi-Activo no cachea como válido un análisis con fallo de ejecución;
- se retira `Estado del análisis` del frontend, manteniendo el diagnóstico sólo backend;
- se conservan timeout UI 25 s y single-flight sin retries automáticos.

## Recursos
0 threads nuevos · 0 polling nuevo · 0 LLM nuevo · 0 consultas Supabase nuevas · 0 fan-out nuevo.
