# Commit 17.5.10.3 — Execution ABI Repair + Truthful Pipeline Diagnostics

Base exacta: `f4bfd888dfeeaa8dcbce623ca348aaa9cbc0182a` (Commit ajuste 17.5.10.2).

## Problema raíz confirmado

`TradingExpertSystem.analyze_full_market()` llamó `self.calculate_entry_levels(..., execution_observations=capas)`, pero `FuturesAnalysis.calculate_entry_levels()` conserva la firma legacy sin ese argumento. `MultiAssetAnalysis` hereda de `FuturesAnalysis`, por lo que el mismo fallo alcanzó ambos mercados derivados.

Consecuencia: una tesis LONG/SHORT podía existir y ReviewTrader podía observarla, pero la etapa Entry -> SL -> TP fallaba antes de calcular geometría. Eso no es “mercado sin oportunidades”.

## Corrección

- Bridge ABI sólo para Futures/Multi usando las capas ya cargadas; 0 I/O nuevo.
- El método base recupera `execution_observations` del bridge y conserva Greeks/contexto de ejecución.
- Fallos de geometría runtime se etiquetan `EXECUTION_RUNTIME_FAILED`, no se convierten silenciosamente en “no hay oportunidad”.
- `/api/diagnostics/signal-funnel` y `/api/diagnostics/pipeline-integrity` separan mercado, estrategia, ejecución y runtime.
- Carriles Futures/Multi reciben `pipeline_health` cache-only.
- Frontend muestra “Estado del análisis” con lenguaje técnico convencional.
- Lecturas cacheadas usan 25 s en vez de 15 s, sin reintento automático ni nuevas peticiones.
- BLS 403 se trata fail-open y se desactiva para el resto del proceso tras el primer 403; FOMC/noticias continúan.

## Greeks

No se añade Delta/Gamma/Theta a la justificación direccional en este commit. Sigue siendo contexto de opciones: puede ayudar a interpretar zonas de sensibilidad, pero todavía no tiene autoridad OOS point-in-time para afirmar por qué una señal es LONG/SHORT ni para mover Entry/SL/TP. El gráfico se conserva.

## Recursos

0 threads nuevos, 0 polling nuevo, 0 LLM nuevo, 0 consultas Supabase nuevas, 0 fan-out de red nuevo.
